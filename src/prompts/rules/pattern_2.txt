--------------------------------
STEP 0 — ZOOM FIRST (MANDATORY)
--------------------------------

This is a HUGE drawing sheet. The footing schedule is a THIN HORIZONTAL BAND
near the BOTTOM of the sheet, just above the COL. MARK row.

The full image is too downscaled to read accurately. You MUST:
1. zoom_region into the bottom footing band first.
2. zoom_region into EACH column cell before reading its values.
3. confirm_read the exact text from each zoom before calling add_footing.

DO NOT read footing values from the full image — you will misread them.

The footing data lives ONLY in these rows (left-side labels):
  FOOTING SIZE
  P.C.C. SIZE
  DEPTH (d TO D)
  REINF. //B
  REINF. //L
  FOOTING MIX.

WARNING — common mistake:
The reinforcement is in REINF. //B and REINF. //L rows (format like "25-10 TOR").
Do NOT read reinforcement from the COLUMN sections above (the "X TOR Y @ 75",
"10-20 TOR", ring/link, or pedestal HORI./VERTI. STEEL rows). Those are NOT footing steel.

If every column ends up with the SAME reinforcement, you read the wrong rows. Re-zoom.

CRITICAL RULE:
This table MUST be read COLUMN BY COLUMN.
Never read row-wise.

--------------------------------
STEP 1 — COLUMN LOCKING
--------------------------------

Locate the row named:

COL. MARK

Example:
C1 | C2 | C2A | C3 | C4 | C5 ...

These define EXACT vertical columns.

Create one footing object PER column mark.

You MUST NOT shift values between columns.

If a column has no values above it,
all properties must remain NULL.

--------------------------------
STEP 2 — IGNORE THESE ROWS COMPLETELY
--------------------------------

Do NOT read anything from:

PEDESTAL SIZE
CONC. MIX
HORI. STEEL
VERTI. STEEL
P.C.C SIZE

These rows DO NOT belong to footing data.

--------------------------------
STEP 3 — CHECK COLUMN CONTENT
--------------------------------

Inside each locked column, FIRST look for numeric footing data:
a FOOTING SIZE like "2600 X 3100", a DEPTH like "230 TO 1050" or "750 SOLID",
and REINF rows like "25-10 TOR".

CASE A — Column HAS numeric footing data:
  Extract it normally (size, depth, reinforcement, mix).
  IMPORTANT: A column may show BOTH real footing data AND a "REFER RAFT FOOTING
  PLAN ..." note in an adjacent sub-cell (this happens for C2, C4, etc.).
  In that case the column DOES have footing data — extract the numeric values.
  Do NOT null it just because a REFER note also appears.

CASE B — Column has ONLY a refer/detail note and NO numeric footing data:
  If the entire column cell is just one of:
    REFER RAFT FOOTING PLAN
    REFER COMBINED FOOTING
    REFER FOOTING PLAN
    DETAIL SECTION
  (with no FOOTING SIZE / DEPTH / REINF numbers anywhere in that column),
  then this column has NO footing data. Return:
    size = null
    reinforcement = empty
    mix = null

Rule of thumb: if you can see a numeric FOOTING SIZE in the column, it is CASE A.
Examples from a typical sheet:
  C1  -> only "REFER RAFT FOOTING PLAN ..."          -> CASE B -> null
  C2  -> "2600 X 3100 ... 25-10 TOR ..." + refer note -> CASE A -> extract data
  C2A -> only "REFER RAFT FOOTING PLAN ..."          -> CASE B -> null
  C3  -> only "REFER RAFT FOOTING PLAN ..."          -> CASE B -> null
  C4  -> "2600 X 3100 ... 31-12 TOR ..." + refer note -> CASE A -> extract data

MANDATORY — footing_cell_text field:
For EVERY column, copy the exact raw text you read in that column's footing block
into the add_footing field "footing_cell_text" (verbatim, including any REFER note).
Example for C1: "REFER RAFT FOOTING PLAN OF RAFT-6, RAFT-7, CF-2 CF-3 & DETAIL SECTION"
Example for C2: "2600 X 3100  2750 X 3250  230 TO 1050  25-10 TOR  21-10 TOR  M25"
This is used to verify the column — never copy a neighbour column's text.

--------------------------------
STEP 4 — SIZE EXTRACTION
--------------------------------

From row:

FOOTING SIZE

Format (example):
2600 X 3100

width = first number   (2600)
length = second number  (3100)

Read the ACTUAL numbers in each column — do not assume the example values.
Ignore PCC sizes completely.

--------------------------------
STEP 5 — DEPTH EXTRACTION
--------------------------------

From row:

DEPTH (d TO D)

The footing depth is the SMALLER value (the shallow edge "d").

Map to the add_footing tool fields like this:
  depth_bottom = the SMALLER number   (this becomes the reported depth)
  depth_top    = the LARGER number

Cases:

1)
230 TO 1050
→ depth_bottom = 230  (smaller)  ✓ reported depth = 230
→ depth_top    = 1050 (larger)

2)
750 SOLID
→ depth_bottom = 750
→ depth_top    = 750

IMPORTANT: Always put the SMALLER number in depth_bottom, regardless of whether
it is written first or second. Never report the larger value as the depth.

--------------------------------
STEP 6 — REINFORCEMENT
--------------------------------

Format example:

25-10 TOR
18-10 TOR

Convert to:

25-10T
18-10T

Spacing is NEVER present in this pattern.

Always return:

"spacing": []

--------------------------------
STEP 7 — MIX
--------------------------------

If footing values exist in column:

extract mix like:
M25

If column is REFER PLAN → mix = null

--------------------------------
STEP 8 — IMPORTANT VALIDATION
--------------------------------

Before returning:

Check visually:

Does this column truly contain numeric footing values?

If NO → return NULL footing.

DO NOT GUESS.
DO NOT COPY FROM NEIGHBOUR COLUMN.
